# 前端卡与前端模式

**前端卡**是酒馆生态里用 HTML/CSS/JS 写的富交互卡片（状态栏、数值面板、选项按钮、小游戏等），通常以 ``` 围栏的 HTML 文档形式出现在消息里。本分支只有**一条**渲染路径：原生消息列表 + 逐条内嵌面板。

## 渲染方式

消息列表始终是原生 Compose 滚动视图。含卡的那条消息在气泡位置挂一个 WebView 渲染卡片，高度随内容自适应，卡片外的正文照常走 Markdown。

不再有「整块消息区交给一个 WebView」的专属模式：那种做法要么和原生消息列表重复实现一遍气泡、长按菜单、分支切换，要么把功能砍掉；逐条内嵌让原生侧的一切（复制、编辑、分支、删除、引用、搜索）继续可用。

## 两个模式

**助手详情 → 基础设定 → 华灯兼容模式**：

| 模式 | 行为 |
| --- | --- |
| **华灯兼容模式**（默认） | 卡片渲染成网页，酒馆接口全部可用 |
| **纯原生界面** | 卡片只按文本显示源码，不建 WebView |

这是助手级设置，不同助手可以不同。旧版本的四个取值（自动识别 / 总是 / 酒馆 / 从不）在读取时自动折算：**从不 → 纯原生界面**，其余一律 → **华灯兼容模式**，不需要手动迁移。

## 装载策略

卡片不是「出现即挂 WebView」，而是排队装载：

- **串行**：同一时刻只装载一个面板，先等运行时宿主就绪，再逐个放行，面板之间留冷却间隔。多条消息各带一张卡时不会同时起一堆 WebView。
- **池化**：活跃面板有上限，超出按最近使用淘汰；滑出屏幕的面板会被解挂缓存（保留 DOM，不销毁），滑回来直接复用。
- **占位反馈**：装载中的面板显示占位卡，文案依次是「按序排队加载 → 等待宿主就绪 → 正在装载 → 挂载 DOM → 资源加载中 → 已就绪」，排队中的面板可以点「优先加载」插队。
- **崩溃兜底**：渲染进程异常退出会自动重建；连续多次失败后停止自动重试，只留「手动重新加载面板」。

## 重载面板

面板右上角操作条与占位卡上都有重载入口，做三件事：清掉该楼层的高度缓存、销毁该卡已解挂的 WebView、换一个 WebView 实例重新装载文档。卡里脚本报错（脚本异常提示）或布局算错高度时，点它即可，不必退出会话。

## 卡片里能用的东西

卡片会拿到一层 TavernHelper 兼容接口（`TavernHelper` 与 `SillyTavern` 互为别名）：

```js
TavernHelper.triggerSlash('/send 我选择向东走');   // 斜杠命令
TavernHelper.sendMessage('一行台词');                // 直接发消息
TavernHelper.getVariables();                        // 读变量
TavernHelper.setVariables({ hp: 42 });              // 写变量
```

变量按楼层保存：旧消息显示旧状态、新消息显示新状态，卡片被回收重组后仍能恢复。卡片里的表单（input / change / submit / button）也会回传原生侧——写变量直接落到该楼层，点按钮的文本进聊天输入框。

## 宏

普通消息与卡片内容都走同一套宏展开，酒馆静态宏与常用动态宏可用：

| 类别 | 宏 |
| --- | --- |
| 角色与人设 | `{{char}}` `{{user}}` `{{persona}}` `{{description}}` `{{personality}}` `{{scenario}}` `{{mesExamples}}` `{{charPrompt}}` |
| 时间 | `{{time}}` `{{date}}` `{{weekday}}` `{{isotime}}` `{{isodate}}` |
| 变量 | `{{getvar::名字}}` `{{setvar::名字::值}}`（含 global 变体） |
| 随机 | `{{roll:1d20}}` `{{roll:2d6+1}}` `{{random:a,b,c}}` `{{pick:a,b,c}}` |
| 其他 | `{{model}}` `{{lastMessage}}` `{{newline}}`、注释宏 `{{// ... }}` |

`{{setvar}}` 在渲染前先写入，因此同一段内容里「先设后用」也成立。

## 渲染范围

- 卡片外的正文走本分支的 Markdown 渲染（标题、列表、表格、引用、代码块、加粗斜体删除线、链接图片），不引第三方库，离线可用。
- 正则、上下文组装、宏、世界书注入都发生在原生侧，页面只负责展示——模型实际看到的内容不受卡片渲染影响。
- 生成中的半截 HTML 不交给 WebView（会渲染出残缺网页），生成结束后才装载。
