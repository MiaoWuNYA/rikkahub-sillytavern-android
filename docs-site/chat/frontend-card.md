# 前端卡与前端模式

**前端卡**是酒馆生态里用 HTML/CSS/JS 写的富交互卡片（状态栏、数值面板、选项按钮、小游戏等），通常以 ``` 围栏的 HTML 文档形式出现在消息里。本分支对它有两条渲染路径，互不冲突。

## 两种渲染方式

| 方式 | 行为 | 适用 |
| --- | --- | --- |
| **逐条内嵌（原版行为，始终保留）** | 消息列表照常滚动，含卡的那条消息在气泡位置挂一个 WebView 渲染卡片，高度随内容自适应 | 偶尔出现卡片的普通会话 |
| **前端卡专属模式** | 整块消息区交给**一个** WebView 渲染（消息气泡 + 卡片同页），标题栏与输入框仍是原生控件 | 卡片占主体、或卡片较多的会话 |

专属模式解决的是「一条消息一个 WebView」的老问题：多个 WebView 同时存活时硬件层叠加不稳定，界面容易闪退；整页只有一个 WebView 后这类问题不再出现，输入栏的模糊/玻璃效果会自动让位（采样 WebView 硬件层会崩，属于已知限制）。

## 怎么进入专属模式

- **导入角色卡时自动**：导入的卡（含其世界书与预置消息）里检测到前端卡时，会自动为该助手打开前端模式，并弹出「已自动切换前端模式」提示。
- **手动开启**：**设置 → 华灯设置 → 兼容与辅助 → 前端卡专属模式**，打开后所有会话都走 WebView 渲染。
- 会话**中途**出现的卡片不会改变渲染方式——避免聊到一半界面突然换掉。想切换方式，改上面的开关即可。

## 卡片里能用的东西

卡片 iframe 会注入一层薄桥，让现成的酒馆卡不必为本地改写：

```js
// 直接可用（TavernHelper 与 SillyTavern 互为别名）
TavernHelper.triggerSlash('/send 我选择向东走');   // 斜杠命令回传
TavernHelper.sendMessage('一行台词');                // 直接发消息
TavernHelper.getVariables();                        // 读变量
TavernHelper.setVariables({ hp: 42 });              // 写变量
```

变量保存在本机 WebView 存储里，跨消息保持。

斜杠命令目前只执行 `/send`（其余命令会在界面上如实提示未支持，不会静默失败）。

## 前端插件脚本

插件可以声明 `frontend.scripts`（见「插件」文档），只在该专属模式下注入页面执行。脚本拿到的是与酒馆助手同名的 `TavernHelper` / `SillyTavern` 接口与事件，用来兼容 JS-Slash-Runner 那类前端插件；原生消息区、上下文组装与工具调用都不受影响。

## 宏

普通消息与卡片内容都走同一套宏展开，酒馆静态宏与常用动态宏可用：

| 类别 | 宏 |
| --- | --- |
| 角色与人设 | `{{char}}` `{{user}}` `{{persona}}` `{{description}}` `{{personality}}` `{{scenario}}` `{{mesExamples}}` `{{charPrompt}}` |
| 时间 | `{{time}}` `{{date}}` `{{weekday}}` `{{isotime}}` `{{isodate}}` |
| 变量 | `{{getvar::名字}}` `{{setvar::名字::值}}`（含 global 变体） |
| 随机 | `{{roll:1d20}}` `{{roll:2d6+1}}` `{{random:a,b,c}}` `{{pick:a,b,c}}` |
| 其他 | `{{model}}` `{{lastMessage}}` `{{newline}}`、注释宏 `{{// ... }}` |

`{{setvar}}` 在渲染前先写入，因此同一段内容里「先设后用」也成立。

## 渲染范围

- 卡片外的正文走本分支的 Markdown 渲染（标题、列表、表格、引用、代码块、加粗斜体删除线、链接图片），不引第三方库，离线可用。
- 正则、上下文组装、宏以外的注入都发生在原生侧，页面只负责展示——**两套渲染方式共用同一份已处理文本**，切换方式不会改变模型实际看到的内容。

::: warning 已知限制
专属模式下消息区的长按操作（复制、编辑、分支、删除）暂未提供，需要这些操作时用设置里的开关切回逐条内嵌方式。
:::
