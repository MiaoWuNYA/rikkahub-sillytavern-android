# 提示词缓存：长对话省 token 的关键

DeepSeek、Kimi、Claude 等服务商都提供前缀缓存：本次请求与上次**逐字节一致**的开头部分按大幅折扣计费。华灯逐个消除聊天场景中导致前缀变化的分叉点，让长对话稳定命中缓存。

## 缓存为什么容易失效

普通聊天客户端里，大量内容每一轮都在变：时间戳、随机数、最近会话引用、记忆注入、滚动摘要……只要请求开头有一个字符不同，缓存就从那个位置全部作废，整段历史按原价重算。

华灯在生成请求前对这些动态内容做了系统性处理：

| 分叉点 | 处理方式 |
| --- | --- |
| 最近会话 / 记忆引用等动态注入 | **冻结锚点**：旧块原位保留，新内容追加到尾部，不再随历史后移 |
| `{{random}}` / `{{pick}}` 等随机宏 | 按消息固定取值，历史消息不再每轮重掷 |
| 世界书 / 技能 / 跨窗口记忆 / OCR / 正则 depth | 按「用户轮」冻结，同一轮内多次请求前缀一致 |
| 时间族宏（`{{time}}` 等） | 5 分钟粒度对齐，避免秒级抖动 |
| 滚动压缩摘要 | 追加式衔接，跨压缩保持 token 前缀稳定 |
| 记忆全量注入 / Recent Chats | 移出前缀区（前者移到上下文尾部） |
| 多 API Key | 按会话粘性选 Key，避免切换账号导致上游缓存失效 |
| Claude 思维链块 | 保留并回放 `redacted_thinking`，不破坏结构 |

## 怎么开启

缓存友好的时间宏与随机宏处理**默认开启**（助手级开关，见助手编辑页）。你不需要做任何事，长对话的成本就已经比普通客户端低。

::: info 实际效果因对话形态而异
稳定、纯追加的聊天场景提升最明显；如果每轮都在改系统提示词或大规模编辑历史，缓存自然难以命中。具体幅度取决于内容变化频率与供应商定价。
:::

## 缓存分叉诊断

怀疑缓存没命中？打开**聊天抽屉 → 菜单 → 提示词查看器**：它以网页形式展示本轮发给模型的完整请求，并内置**前缀分叉诊断**——逐条对比相邻两轮请求：

- 定位第一条**分叉消息**（第几条、什么角色、每次请求都在变化）；
- 显示公共前缀长度与**估算可命中的前缀 tokens**；
- 自动分类分叉原因——缓存为什么断，变成可观察的事实。

首次请求没有上次快照可比对，发送下一轮后再打开即可看到分叉位置。
