# 华灯设置：本分支开关的统一入口

**设置 → 华灯设置** 只保留一个分组**接入与自动化**，六个入口：**Jev 智能决策、微信 Bot、QQ Bot、兼容与辅助、酒馆助手、安全设置**。

- **兼容与辅助**（**设置 → 华灯设置 → 兼容与辅助**）是全局开关页，下面的开关表就是该页内容；全局开关对所有助手生效，助手编辑页的对应开关可单独覆盖。
- 用户人设、群聊、导演备注、主动消息已移到 **设置 → 酒馆功能**，见[人设与导演备注](/assistants/persona)、[群聊](/assistants/group-chat)。

## 兼容与辅助

| 开关 | 说明 | 默认 |
| --- | --- | --- |
| **酒馆模式（纯净请求）** | 开启后请求只发送：角色卡（含世界书 / 示例消息 / 系统提示）、聊天历史、工具的最小可用定义——插件提示词、记忆检索、跨窗口生活流、宏以外的全部注入、工作空间提醒、时间提醒、作者注释、技能自动触发、文档转 Prompt、OCR、Recent Chats、滚动压缩摘要、工具路由与工作伦理区、工具系统提示词等**全部不再发送**。适合角色扮演与创作，避免工作流噪声干扰生成质量 | 关 |
| **酒馆模式·保留工具** | 配合酒馆模式使用：保留文件 / 搜索 / 网页抓取 / 计算器等基础工具的 JSON 定义（不发送工具提示词）。关闭后退化为纯文本模型，请求中不含任何工具；仅在酒馆模式开启时可切换 | 关 |
| **中转站兼容** | Gemini 经 OpenAI 兼容中转（newapi 等）接入时的三类经典病态自动修复：① 正文被 `reasoning_content` 吞掉——流结束后正文为空而推理有实质内容时，自动把推理提升为正文；② `response` 前缀伪影——流式与非流式路径均自动剥离，带边界判定不误伤英文单词；③ 正文截断——提升与剥离后回复完整呈现 | 关 |
| **防空回复** | 两件事：**系统提示词入对话流**（SYSTEM 消息原位转为 user 轮 + 模型确认轮，注入位置与内容不变，绕开 Gemini 对 `systemInstruction` 的安全拦截）；**空回复自动微扰重试**（对末条用户消息做标点微扰，4 变体轮换，至多重试 3 次） | 关 |
| **上下文瞬态内容裁剪** | 超过两轮的网页搜索结果、图片、音视频不再随每次请求发送，替换为占位说明与消息 ID；AI 可用 `read_history_message` 工具取回原文。大幅减少图片与搜索类长对话的 token 消耗 | 开 |
| **清爽简洁模式** | 隐藏情侣空间、生活空间等娱乐入口，且不再向 AI 注册对应工具——界面更简洁，上下文更省 | 关 |
| **工具结果截断** | 工具输出超过 32KB 自动截断并保存到文件；中转站导致工具调用异常时可尝试关闭 | 开 |
| **系统提示词转义** | 把系统消息中的 `<` `>` 转为 HTML 实体，绕过中转站 WAF 拦截——遇到 `upstream_content_rejected` 报错时开启 | 关 |
| **提示可用的 Python 库** | 在 `execute_python` 的工具描述里列出已内置的库（numpy / pandas / pillow / docx / pdf / yaml 等）；关掉可省每次请求几百 token | 开 |

::: tip 什么时候开「中转站兼容」
只有当你通过 OpenAI 兼容中转接入 Gemini，且观察到「思考里是答案、正文只剩半截」或「正文开头有 response 残留」时才需要开。直连官方 API 或正常供应商时保持关闭。
:::

::: info 前端卡（华灯前端内核）不在这里配置
前端卡模式现在是**助手级**设置，在 **助手详情 → 基础设定 → 华灯前端内核**（自动识别 / 总是 / 从不）。见[前端卡与前端模式](/chat/frontend-card)。
:::

## 接入与自动化

- **Jev 智能决策**：TypeSafe System One 判断模型的接入配置页，见[Jev 智能决策](/memory/jev)；
- **微信 Bot / QQ Bot**：把助手接入消息通道，见[手机增强](/extensions/toolbox)；
- **酒馆助手**：前端卡渲染、流式、代码折叠与宏替换等酒馆助手兼容项；
- **安全设置**：全局工具调用审批策略，见下。

## 安全设置

全局工具调用审批策略，两项互斥：

- **强制确认所有工具调用**：每次执行前都要确认——接入了来源不明的 MCP / 插件时建议开启；
- **自动批准所有工具调用**：跳过审批（默认开启）。

无论策略如何，剪贴板 / 屏幕时间 / Shell 等敏感操作都会单独要求审批；文件工具的写入类操作同样需要审批。
